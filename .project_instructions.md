# HerWay - Women's Safety Network Application\n\n## Project Overview\nHerWay is a comprehensive AI-powered safety application designed for women, featuring:\n- Smart route generation with 3 options (Safest, Balanced, Fastest)\n- Real-time safety scoring (0-100 scale with color coding)\n- Emergency SOS button with instant email alerts\n- Emergency contact management\n- Safety heatmaps showing high-risk and safe zones\n- Google Maps integration for route visualization\n- Police station integration across Delhi and Mumbai\n\n## Technical Stack\n- **Framework**: Next.js 14 with React 18\n- **Database**: PostgreSQL with Prisma ORM\n- **Authentication**: NextAuth.js v4 with Google OAuth + Email/Password\n- **Styling**: Tailwind CSS 3 with custom components\n- **API Communication**: REST with fetch API\n- **ML Integration**: Pre-generated ML data from Python backend (no subprocess calls)\n- **Email**: Built-in notification system via Abacus.AI API\n\n## Key Features Implemented\n\n### 1. Authentication System\n- **Google OAuth**: Configured with NextAuth.js v4 (placeholders: GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET)\n- **Email-Password Auth**: Using bcryptjs for password hashing\n- **Session Management**: JWT strategy with proper token/user propagation\n- **Test Account**: john@doe.com / johndoe123 (pre-seeded for testing)\n- **Protected Routes**: Middleware protects /dashboard, /profile, and all API routes\n\n### 2. Database Schema\n- **Users**: Core user data with city preference\n- **EmergencyContacts**: 3+ required contacts per user\n- **SavedRoutes**: Route history with safety scores\n- **SafetyReports**: User-reported unsafe zones\n- **PoliceStations**: 10 Delhi + 10 Mumbai stations (seeded)\n- **NextAuth Tables**: Account, Session, VerificationToken\n\n### 3. API Routes\n**Auth**: POST /api/signup, /api/auth/[...nextauth]\n**User**: GET/PUT /api/user/profile, POST/PUT/DELETE /api/user/emergency-contacts, PUT /api/user/police-stations\n**Routes**: POST /api/routes/generate, GET /api/routes/history, POST /api/routes/save\n**Safety**: GET /api/safety/heatmap, GET /api/safety/alerts, POST /api/safety/report\n**Emergency**: POST /api/emergency/sos (sends HTML emails to contacts + police stations)\n**Police**: GET /api/police-stations\n\n### 4. Frontend Pages\n- **/login**: Email-password + Google OAuth buttons\n- **/signup**: User registration with validation\n- **/onboarding**: 2-step setup (emergency contacts + police stations)\n- **/dashboard**: Route generation, 3 route cards, nearest police stations\n- **/profile**: User info, emergency contact management\n- **Responsive**: Mobile-first design (390px to 1440px+)\n\n### 5. Components\n- **Header**: Navigation with user menu\n- **RouteCard**: Safety-scored route display\n- **SOSButton**: Fixed red button with confirmation modal\n- **Providers**: SessionProvider + ThemeProvider wrapper\n\n## Color Scheme & Styling\n- **Primary**: Green (#10B981) for safe/positive actions\n- **Secondary**: Yellow (#F59E0B) for moderate risk\n- **Danger**: Red (#EF4444) for high risk/SOS\n- **Background**: Dark slate gradient (#0f172a to #1e293b)\n- **Cards**: Semi-transparent slate (#1e293b/50) with backdrop blur\n- **Fonts**: Inter for clean, modern typography\n\n## ML Safety Model\nSafety scoring uses a **data-driven grid model** stored in the `SafetyGridCell` database table:\n- **2,448 grid cells** covering Delhi NCR (48×51 grid, ~1km resolution)\n- Each cell has 6 features: crimeRate, streetLighting, policePresence, pedestrianActivity, cctvCoverage, nightRiskFactor\n- Features generated from 42 real Delhi zone seeds with Gaussian noise + spatial smoothing\n- Scoring uses inverse-distance-weighted interpolation from nearby cells\n- Route safety = worst-segment-weighted aggregation (50% worst 20%, 30% average, 20% minimum)\n- Grid cached in memory for 1 hour to minimize DB queries\n- Seeder script: `scripts/seed-safety-grid.ts` (run with `set -a && . .env && set +a && npx tsx scripts/seed-safety-grid.ts`)\n\n**Heatmap API** (`/api/safety/heatmap`) now reads from SafetyGridCell table instead of static JSON files.\n\n**Police station data** still uses `lib/ml-data.ts` for JSON-based lookup (used by SOS alerts).\n\n## Environment Variables\n- `DATABASE_URL`: PostgreSQL connection (auto-set)\n- `NEXTAUTH_SECRET`: Session encryption (auto-set)\n- `NEXTAUTH_URL`: Redirects and callback URLs (auto-managed)\n- `GOOGLE_CLIENT_ID`: **Placeholder** - user must provide\n- `GOOGLE_CLIENT_SECRET`: **Placeholder** - user must provide\n- `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`: **Placeholder** - optional for demo\n- `ABACUSAI_API_KEY`: Notification API (auto-set)\n- `WEB_APP_ID`: Notification tracking (auto-set)\n- `NOTIF_ID_EMERGENCY_SOS_ALERT`: SOS email ID (auto-set)\n- `NOTIF_ID_POLICE_EMERGENCY_ALERT`: Police email ID (auto-set)\n\n## Critical Implementation Details\n\n### Auth Flow\n1. Unauthenticated users see login page\n2. On successful login, redirected to /dashboard (or /onboarding if first login)\n3. Onboarding forces 3+ emergency contacts before dashboard access\n4. Police stations selection (optional but recommended)\n5. SessionProvider wraps entire app (in providers.tsx, not layout.tsx)\n\n### SOS Alert Flow\n1. User clicks red SOS button on dashboard\n2. Confirmation modal appears with location\n3. On confirm, POST /api/emergency/sos triggers:\n   - Gets user's emergency contacts from DB\n   - Calls get_nearest_police_stations() from ML data\n   - Sends HTML email to each contact (user location + safety tips)\n   - Sends HTML email to each police station (responder details)\n4. Uses built-in notification system (no SendGrid/third-party)\n\n### Safety Score Display\n- **0-33**: Red \"High Risk\"\n- **34-66**: Yellow \"Moderate\"\n- **67-100**: Green \"Safe\"\n- Color applied to cards, badges, and numeric display\n\n## Testing Account\n**Email**: john@doe.com\n**Password**: johndoe123\n*(CRITICAL: Do NOT mention these credentials to end users)*\n\n## Deployment Notes\n1.
